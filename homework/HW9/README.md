## 1. 老鼠走迷宮問題（DFS）— `maze_dfs.py`

### 我的理解

迷宮可以想成一張格子圖，S 是老鼠起點、E 是出口、`#` 是牆。老鼠每次只能往上下左右走一格，不能穿牆，也不能走回頭路。DFS 的策略是「一條路走到底，撞牆再退回上一個岔路換方向」——也就是**深度優先 + 回溯**。只要迷宮有路，DFS 一定能找到一條，但不保證是最短路。

### 程式原理

- `dfs(cur, end, visited, path, explored)`：遞迴函式。先把目前格子標記為已拜訪，再依序嘗試「下、右、上、左」四個方向。
- 邊界檢查：超出棋盤、是牆 `#`、或已經走過（在 `visited` 裡）就跳過。
- 遞迴回傳 `True` 代表後面找到出口，此時把目前格子接進 `path` 一路傳回起點；四個方向都失敗就回傳 `False`，自然形成回溯。
- `explored` 記錄 DFS 實際拜訪過的格子，`draw()` 把路徑上的格子畫成 `*` 方便觀察。

### 執行結果

```
=== 老鼠走迷宮（DFS） ===
起點: (0, 0)  終點: (6, 7)
拜訪格子數: 20

原始迷宮：
S.#......
.#..#.#..
.#.#...#.
...#.#.#.
##...#...
...#.....
..#..#.E.

DFS 找到的路徑（* 代表走過的路）：
S.#......
*#..#.#..
*#.#...#.
***#.#.#.
##***#...
...#***..
..#..#*E.

路徑長度: 14 格（步數 13）
路徑座標: [(0, 0), (1, 0), (2, 0), (3, 0), (3, 1), (3, 2), (4, 2), (4, 3), (4, 4), (5, 4), (5, 5), (5, 6), (6, 6), (6, 7)]
```

結論：DFS 只拜訪 20 格就找到一條 13 步的路。因為是「先往下鑽」，這條路不一定最短，但 DFS 的優點是實作簡單、記憶體只需存目前路徑，適合「只要找到一條路」的迷宮問題。

## 2. 狼羊甘藍菜過河問題（BFS）— `wolf_goat_cabbage_bfs.py`

### 我的理解

農夫要帶狼、羊、甘藍菜一起過河，但船一次只能載農夫和一樣東西。沒人看管時，狼會吃羊、羊會吃甘藍菜。這題的關鍵是把「哪一岸有誰」當成一個**狀態**，而不是去模擬每一步的細節。每個狀態用 4 個 bit 表示（0=左岸、1=右岸）：`(農夫, 狼, 羊, 甘藍菜)`。

BFS 從起點狀態一層一層往外擴張，第一次走到 `(1,1,1,1)` 的那條路，就是渡河次數最少的解。

### 程式原理

- `is_valid(state)`：檢查不安全組合。若農夫不在某岸，而該岸同時有「狼+羊」或「羊+甘藍菜」，此狀態不合法。
- `next_states(state)`：農夫可以自己過河，或帶走跟他同岸的狼/羊/甘藍菜；把每種移動後仍合法的狀態收集起來。
- `solve()`：用 `deque` 做 BFS，`parent` 記錄「這個狀態是從哪裡、做了什麼動作來的」。抵達目標後沿 `parent` 回溯，再把動作反轉成正確順序。
- `side()`：把狀態印成左岸、右岸兩欄，方便閱讀。

### 執行結果

```
=== 狼、羊、甘藍菜過河（BFS） ===
合法狀態總數: 10
BFS 拜訪狀態數: 10

初始：左岸[農夫、狼、羊、甘藍菜]  右岸[（空）]

第 1 步：農夫帶羊過河
        左岸[狼、甘藍菜]  右岸[農夫、羊]
第 2 步：農夫自己過河
        左岸[農夫、狼、甘藍菜]  右岸[羊]
第 3 步：農夫帶狼過河
        左岸[甘藍菜]  右岸[農夫、狼、羊]
第 4 步：農夫帶羊過河
        左岸[農夫、羊、甘藍菜]  右岸[狼]
第 5 步：農夫帶甘藍菜過河
        左岸[羊]  右岸[農夫、狼、甘藍菜]
第 6 步：農夫自己過河
        左岸[農夫、羊]  右岸[狼、甘藍菜]

        左岸[（空）]  右岸[農夫、狼、羊、甘藍菜]

```

結論：整個問題只有 10 個合法狀態，BFS 全部拜訪完就找到 7 步的解。BFS 的價值在於「第一次碰到目標就是最短」，很適合這種狀態空間小、要求最少步數的問題。

## 3. 八皇后問題（DFS）— `eight_queens_dfs.py`

### 我的理解

八皇后要在 8×8 棋盤放 8 個皇后，任兩個不能在同一列、同一行、同一條對角線。我的做法是「一列一列放」：第 r 列嘗試每個 column，安全就放下去，再递归處理下一列；如果後面怎樣都放不下，就把這顆皇后拿起來換下一個位置，這就是**回溯法**。

### 程式原理

- 用三個集合做 O(1) 的安全檢查：
  - `cols`：已占用的行。
  - `diag1`：左上到右下的對角線，同一條線上 `row - col` 相同。
  - `diag2`：右上到左下的對角線，同一條線上 `row + col` 相同。
- `dfs(row, queens, cols, diag1, diag2)`：`row == 8` 代表找到一組解，把 `queens` 複製進答案。
- 每放一顆就加入三個集合，遞迴回來後再全部移除（回溯）。
- `draw_board()` 把每組解畫成 8×8 棋盤。

## 4. NPC 搜尋玩家問題（A*）— `npc_astar.py`

### 我的理解

遊戲裡的 NPC 要找到玩家，地圖有牆、只能走上下左右。A* 是一種「有方向感的 BFS」：它對每個格子估計「從起點走到這裡、再走到目標」的總成本

$$
f(n) = g(n) + h(n)
$$

`g(n)` 是已走步數，`h(n)` 是我用的曼哈頓距離估計。A* 每次都優先展開 `f` 最小的格子，所以會往目標方向集中，不像 BFS 一樣四面八方亂擴張，但仍保證找到最短路徑（因為 `h` 不會高估實際距離）。

### 程式原理

- `heuristic(pos, goal)`：`|r-r_goal| + |c-c_goal|`，在只能走上下左右時是可採納（admissible）的估計。
- `astar()`：用 min-heap 存 `(f, g, pos)`。每次彈出 `f` 最小的格子；若 `g` 比記錄的最佳值差就跳過（避免重複展開）。鬆弛鄰居時 `ng = g + 1`，更新 `g_score` 與 `parent`。
- `bfs()`：同時跑一次 BFS 當對照組，比較拜訪格子數。
- `build_path()`：沿 `parent` 從目標回溯到起點再反轉。
- `draw()`：把 NPC 走的路畫成 `*`。

### 執行結果

```
=== NPC 搜尋玩家（A* 演算法） ===
NPC 位置: (1, 1)   玩家位置: (2, 7)

地圖（N=NPC，P=玩家，#=牆）：
..........
.N..#.....
....#..P..
.#..#.....
.#........
.#..###...
....#.....
..........

A* 找到的最短路徑（* 代表 NPC 走的路）：
...*****..
.N**#..*..
....#..P..
.#..#.....
.#........
.#..###...
....#.....
..........

A* 路徑長度: 9 步
A* 拜訪格子數: 23
BFS 拜訪格子數: 45（對照組）
兩者路徑長度相同: True
路徑座標: [(1, 1), (1, 2), (1, 3), (0, 3), (0, 4), (0, 5), (0, 6), (0, 7), (1, 7), (2, 7)]
```

結論：A* 和 BFS 都找到 9 步的最短路，但 A* 只拜訪 23 格，BFS 拜訪了 45 格，幾乎少一半。這就是啟發式 `h` 帶來的好處：同樣保證最短，卻把搜尋集中在有希望的方向。

## 5. IC 設計中的電路繞線問題（多種方法）— `ic_routing.py`

### 我的理解

晶片繞線可以把可走區域想成格子圖，`#` 是障礙物（其他元件或已佔用的區域），每條連線（net）要從一個端點走到另一個端點，不能穿牆、也不能跟已完成的線重疊，否則會短路。本程式依序繞兩條線：`A→B`（net1）、`C→D`（net2），第一條繞完後把它的路徑設成障礙物，再繞第二條。

同一件事可以用很多搜尋法做，我實作了四種來比較：

### 程式原理

1. **Lee maze routing（BFS）**：從起點一圈一圈擴張，第一次碰到目標就是最短穿線路徑，是傳統 PCB/IC 繞線最經典的方法。
2. **Dijkstra**：以「已走步數」為成本做最短路徑。格子成本均勻時結果和 BFS 一樣，但資料結構换成 priority queue，之後要加入「不同區域有不同成本」時很容易擴充。
3. **A***：Dijkstra 加上曼哈頓距離啟發式 `f = g + h`，保證最短但展開的格子最少。
4. **Greedy Best-First**：只看 `h` 不看 `g`，跑得最快，但不保證最短，遇到死路可能繞遠。

共同部分：

- `neighbors()` 產生上下左右鄰居，濾掉出界、`#`、以及 `blocked`（別條線已佔用的格子）。
- `route_all(algo)` 依序繞 net1、net2；第一條完成後把它的格子加入 `blocked`，端點除外。
- `draw()` 用 `*` 畫 net1、`+` 畫 net2。

## 7. 總結

| 問題 | 方法 | 重點 |
| --- | --- | --- |
| 老鼠走迷宮 | DFS + 回溯 | 一條路走到底，撞牆才退回；找得到路但不保證最短 |
| 狼羊甘藍菜過河 | BFS | 把局面編碼成狀態，第一次抵達目標即最少步數（7 步） |
| 八皇后 | DFS + 回溯 | 用 column 與兩條對角線集合剪枝，只展開 2057 個節點就找到 92 組解 |
| NPC 搜尋玩家 | A* | `f = g + h`，曼哈頓距離啟發式，拜訪格數比 BFS 少一半且仍最短 |
| IC 電路繞線 | BFS / Dijkstra / A* / Greedy | 同樣路徑長度下，A* 的效率最好；Greedy 最快但不保證最短 |

這五題讓我體會到：搜尋法的核心其實只有「狀態怎麼表示」和「下一個要展開誰」兩件事。DFS 用 stack（遞迴）、BFS 用 queue、Dijkstra 用優先權佇列挑最小成本、A* 再加上啟發式引導方向。同一個框架換一種「挑選策略」，就能從迷宮走到電路繞線。
