# 第七週習題：動態規劃與文字算法 — diff（LCS v.s. Myers）

我用 opencode

作業要求選一個文字類型問題，分別用「動態規劃」與「非動態規劃」解決，並說明原理、複雜度與比較。我選的是第 1 題 **diff：兩個檔案差異比對**，兩支程式分别是 `diff_lcs.py`（LCS 動態規劃）與 `diff_myers.py`（Myers O(ND)），另有 `compare.py` 負責正確性驗證與效能計時。

---

## 1. 我的理解

### diff 在解什麼

給兩個序列 a、b（本作業逐行比對檔案），找出讓 a 變成 b 的**最短編輯腳本**：只允許「刪除 a 的一行」與「插入 b 的一行」兩種操作（這正是 `diff` 指令與 git diff 的基本模型）。最少要動幾步，這個步數就是**最小編輯距離 D**。相同行數固定是 `n + m - 2 × LCS長度`，所以「找最短編輯腳本」等價於「找最長共同子序列（LCS）」。

### 解法一：動態規劃（LCS）

最直覺的做法是把「a 的前 i 個、b 的前 j 個」的所有子問題答案填成一張表：

- `dp[i][j]` = a[:i] 與 b[:j] 的 LCS 長度
- 若 `a[i-1] == b[j-1]`：這個字元可以接在後面 → `dp[i][j] = dp[i-1][j-1] + 1`
- 否則：只能捨棄 a 的最後一字或 b 的最後一字 → `dp[i][j] = max(dp[i-1][j], dp[i][j-1])`

填完後從右下角往回走：走對角線代表「這行相同」、往左代表「插入」、往上代表「刪除」，就還原出完整對齊結果。這就是標準的**填表 → 回溯**動態規劃。

### 解法二：非動態規劃（Myers O(ND)）

Myers（1986）把 diff 看成**編輯圖上的最短路徑**：橫軸是 a 的位置、縱軸是 b 的位置，走對角線代表相同（免費）、往右代表刪除（代價 1）、向下代表插入（代價 1），從 (0,0) 走到 (n,m) 的最短路徑長度就是 D。

它的關鍵洞察是：**不需要把整張 n×m 的表填滿**。反過來讓編輯距離 d = 0, 1, 2, ... 一層一層擴張——每一層只記錄「對角線 k = x−y 上能走到的最遠點」V[k]（因為每步只會從上一層相鄰對角線過來，走最遠的點一定最有希望）。當某條對角線的最遠點抵達終點 (n,m)，當前的 d 就是答案，再用每層的 V 快照往回走出一條路。這是**貪婪式廣度優先搜尋**，不是填表動態規劃：工作量取決於 d 要擴張幾層，而不是 n×m。

## 2. 程式原理

### `diff_lcs.py`（動態規劃）

- `lcs_table(a, b)`：建 (n+1)×(m+1) 的 dp 表，`dp[i][j] = LCS(a[:i], b[:j])`。
- `diff_lcs(a, b)`：從 `dp[n][m]` 回溯——a[i-1]==b[j-1] 走對角線記 `=`；`dp[i][j-1] >= dp[i-1][j]` 時記 `+`（插入）；否則記 `-`（刪除）。最後 `reverse()` 讓腳本由前往後。
- `show_diff(title, ops)`：印出類似 unified diff 的對齊結果與「共同/刪除/插入」統計，刪+插就是最小編輯距離。
- 主程式：無參數跑三段示範（Myers 論文經典例子、行層級例子、小 dp 表）；接兩個檔案參數時逐行比對兩個檔案。

### `diff_myers.py`（非動態規劃）

- `myers_diff(a, b)`：主迴圈 `d = 0..n+m`，每層開始前把 V 存進 `trace`；對每條對角線 k 決定起步點（k==-d 或左邊比較遠 → 從下方插入過來；否則 → 從左方刪除過來 +1），再沿相同字元「蛇行」前進。一抵達 (n,m) 就停止。
- `_backtrack(trace, a, b, d)`：從第 d 層往回走：比較 `trace[dd]` 在 k−1/k+1 的遠近決定上一步是插入還是刪除，中間跳過對角線的相同元素，最後 `reverse()`。
- 主程式：與 `diff_lcs.py` 相同的三段示範（第三段多印出逐層擴張的 V，可看到 d=3 就碰到終點）+ 檔案比對模式。

### `compare.py`（驗證與計時）

1. 隨機 300 組（長度 0~30、字母表 ABCD）檢查兩演算法的 D 是否一致，且兩份腳本套回 a 都等於 b。
2. 經典例子 `ABCABBA → CBABAC` 比對論文宣稱的 D=5。
3. n=m=3000 行、三種差異程度（小/中/大）各計時兩種演算法。

## 3. 執行結果

### 兩種演算法對同一組輸入的輸出

小例子 `a = ABCABBA`、`b = CBABAC`（Myers 論文的經典例子）：

```
----- LCS 動態規劃：'ABCABBA' vs 'CBABAC' -----
  - A
  - B
  = C
  - A
  = B
  + A
  = B
  = A
  + C
  共同 4 行、刪除 3 行、插入 2 行  ->  最小編輯距離（刪+插）= 5

----- Myers O(ND)：'ABCABBA' vs 'CBABAC' -----
  - A
  - B
  = C
  + B
  = A
  = B
  - B
  = A
  + C
  共同 4 行、刪除 3 行、插入 2 行  ->  最小編輯距離（刪+插）= 5
```

兩者編輯距離都是 5（與論文一致），但腳本長相不同——因為「最短路徑」有多條，LCS 與 Myers 平手時選的路不一樣，這不影響正確性（見下面 300 組隨機驗證）。

### 行層級 diff（兩支程式輸出完全相同）

```
----- 舊檔 vs 新檔 -----
  = the quick brown fox
  - jumps over
  + leaps past
  = the lazy dog
  + and runs away
  共同 2 行、刪除 1 行、插入 2 行  ->  最小編輯距離（刪+插）= 3
```

### Myers 逐層擴張過程（`diff_myers.py` 第三段示範）

```
  d=0: k= 0 -> (1,1)
  d=1: k=-1 -> (1,2)   k= 1 -> (2,1)
  d=2: k=-2 -> (1,3)   k= 0 -> (3,3)   k= 2 -> (3,1)
  d=3: k=-3 -> (1,4)   k=-1 -> (3,4)   k= 1 -> (4,3)   k= 3 -> (4,1)
  -> d=3 時 k=-1 線上的 (3,4) 終點被抵達，最小編輯距離 D=3，停止擴張
```

可以看到每條對角線只留一個「最遠點」，d=3 就停，完全沒有填 3×4 的整張表。

### 檔案比對模式

```bash
python3 diff_lcs.py  a.txt b.txt
python3 diff_myers.py a.txt b.txt
```

兩個檔案輸出相同的對齊結果（共同 3 行、刪 1 插 2、D=3）。

### `compare.py` 正確性驗證

```
===== 1. 正確性驗證（隨機 300 組）=====
  兩種演算法 300 組最小編輯距離全數一致、腳本皆可還原：True

===== 2. 經典例子 =====
  a = ABCABBA, b = CBABAC（Myers 論文宣稱最小編輯距離 = 5）
  LCS/DP 算出 D = 5   Myers O(ND) 算出 D = 5   一致：True
```

### `compare.py` 效能計時（n = m = 3000 行）

```
===== 3. 效能比較（n = m = 3000 行）=====
  A. 小差異（改 20 行）               D=20    LCS/DP   1.3979s   Myers   0.0009s   距離一致：True
  B. 大差異（幾乎全改）               D=6000  LCS/DP   1.3101s   Myers   6.6138s   距離一致：True
  C. 中差異（改 1500 行）             D=3000  LCS/DP   1.4036s   Myers   1.9835s   距離一致：True
```

## 4. 複雜度與比較

| | LCS（動態規劃） | Myers O(ND)（非動態規劃） |
| --- | --- | --- |
| 思路 | 填 dp 表 + 回溯（子問題最優解疊出全域最優解） | 編輯圖最短路徑，按 d 逐層貪婪擴張、記錄每條對角線最遠點 |
| 時間複雜度 | O(n×m)，**與差異多少無關**，一定填滿整張表 | O((n+m)×D)，D = 最小編輯距離 |
| 空間複雜度 | O(n×m)（整張表才能回溯） | O(D²)（只存每層的 V 快照） |
| 差異很小時 | 慢——明明只差 2 行也要算 3000×3000 | 極快——D=20，只跑 20 層（實測快約 1500 倍） |
| 差異很大時 | 穩定，維持 O(n×m) | 反而變慢——D≈n+m 時 O((n+m)²) 且常數較大（實測 6.6s vs 1.3s） |
| 平手時的結果 | 可能選到另一條等長最短路徑 | 同上，兩者編輯距離必相同但腳本可能不同 |
| 實務應用 | 教學、小字串（LCS 也是 bioinformatics 基礎） | GNU diff、git diff 等真實工具的核心演算法 |

計時結果正好驗證理論：動態規劃的耗時固定（1.3~1.4 秒，因為 n×m 不變）；Myers 則從 0.0009 秒（D 小）暴增到 6.6 秒（D≈n+m）。兩條曲線的交叉點大約落在 D ≈ n 附近。

**一句話總結**：動態規劃用「多花空間與固定時間」換取實作單純、結果穩定；Myers 用「只搜尋最短路徑鄰域」換來差異小時的巨大優勢——這也是真實 diff 工具都選 Myers 的原因：日常生活比對檔案時，兩份檔案通常只有少數幾行不同，D 非常小。

## 6. 結論

兩種解法都正確——300 組隨機測資的最小編輯距離全數一致、腳本都能把 a 完整還原成 b，經典例子也與 Myers 論文宣稱的 D=5 吻合。差別在於**成本的形狀**：動態規劃的 O(n×m) 是一筆固定開銷，不管檔案差多少都要付；Myers 的 O((n+m)×D) 則把成本跟「差異程度」綁在一起，差異小時近乎零成本，差異大時反而吃虧。這種「演算法的表現跟輸入的特殊結構（D 的大小）掛鉤」正是非動態規劃方法有時能大幅勝出的關鍵。
